## How it works

Create a webhook endpoint (in Settings, or with the `/webhook_endpoint` API) with a public `https` URL and the
events you want. When one of those events happens we `POST` it to your URL as JSON:

```json
{
  "eventId": "6f1c0a52-3c5e-4d0e-9b53-0c1b8b0a7c11",
  "type": "sign-request-completed",
  "companyUuid": "…",
  "signRequestUuid": "…",
  "signRequestName": "NDA"
}
```

Answer with any `2xx` status within 10 seconds to acknowledge it. Anything else (or no answer) is retried after
30 seconds, 2 minutes, 10 minutes, 30 minutes, 1 hour, 2 hours and 6 hours; after the eighth attempt we stop.
Redirects are not followed. Delivery is at least once, so use `eventId` (also sent as the `Webhook-Id` header)
to ignore an event you have already handled.

## Verify the signature

Every endpoint has a signing secret (`whsec_…`), returned when the endpoint is created. In the app, open the
endpoint and choose **Show secrets** to see it again, or **Replace signing secret** to issue a new one (the old one
stops working immediately). Each request carries:

| Header | Value |
|---|---|
| `Webhook-Signature` | `t=<unix seconds>,v1=<hex HMAC-SHA256>` |
| `Webhook-Id` | The event id |
| `Webhook-Event` | The event type |

The signature is the HMAC-SHA256, keyed with your signing secret, of the string `<t>.<raw request body>`. Compute
it over the raw body exactly as received, compare in constant time, and reject requests whose `t` is more than
five minutes from your clock.

```js
const crypto = require('crypto');

function isFromBatch(rawBody, header, secret) {
  const parts = Object.fromEntries(header.split(',').map((p) => p.split('=')));
  if (Math.abs(Date.now() / 1000 - Number(parts.t)) > 300) return false;
  const expected = crypto.createHmac('sha256', secret).update(`${parts.t}.${rawBody}`).digest('hex');
  return (
    expected.length === parts.v1.length &&
    crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(parts.v1))
  );
}
```

## If your tool cannot check a signature

Some no-code tools can only compare a fixed value. Tick **Send a fixed secret header** on the endpoint (or create
or update it through the API with `useStaticSecret: true`) and we also send a fixed secret (`whsk_…`) in the
`X-Webhook-Secret` header. The API returns it when it is added; the app shows it under **Show secrets**. A signature is stronger, because it also protects the body and cannot be
replayed; use it whenever you can.

## Endpoint URLs

The URL must be `https` and resolve to a public address. Addresses inside private networks, `localhost` and
cloud metadata addresses are refused, both when you save the endpoint and when we deliver.
